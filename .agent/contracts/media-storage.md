# CutMate AI Media Storage And File Safety Contract

This contract freezes CutMate AI MVP local media storage, file access, upload/download/export safety, deletion behavior, and generated artifact hygiene.

It is binding for backend API, local analysis worker, export worker, frontend download integration, and QA tasks that touch media files or generated artifacts.

## Contract Status

- Active workspace: `workspaces/cutmate-ai`
- Storage mode: local-first MVP
- Contract scope: app-local media storage under `.cutmate/**`
- Implementation code: out of scope for this document
- Security review trigger: yes, for file upload, download, paths, generated files, deletion, logs, and local subprocess output

## Core Decisions

- All generated local app state must live under `.cutmate/**` inside the active workspace.
- Source uploads, intermediates, exports, thumbnails, temporary files, models, and the SQLite database must not be stored in public or static web directories.
- The application must use generated IDs for all storage paths. User-provided filenames must never become storage filenames or path segments.
- A single storage helper must resolve every filesystem path used by the API, worker, exporter, thumbnail generation, cleanup, and download flows.
- The storage helper must reject path traversal, absolute paths, encoded traversal, symlinks or junctions, and any resolved path outside the configured storage roots.
- Downloads must be served through authenticated application routes that enforce ownership and deleted-project checks before reading files.
- Project deletion must block user access immediately and physically delete originals, intermediates, outputs, thumbnails, and file DB references within 24 hours.

## Storage Layout

All paths are relative to the active workspace root.

```text
.cutmate/
  cutmate.db
  models/
    <model_id>/
      <model_files>
  storage/
    uploads/
      <project_id>/
        source.<ext>
    intermediates/
      <project_id>/
        <generated_intermediate_artifacts>
    exports/
      <project_id>/
        <generated_export_artifacts>
    thumbnails/
      <project_id>/
        <generated_thumbnail_artifacts>
  tmp/
    <job_id>/
      <generated_temp_artifacts>
```

### Root Ownership

| Root | Purpose | Allowed owner |
| --- | --- | --- |
| `.cutmate/cutmate.db` | SQLite MVP persistence | backend/database layer |
| `.cutmate/models/**` | local model weights and runtime assets | model/runtime setup only |
| `.cutmate/storage/uploads/<project_id>/source.<ext>` | original uploaded video | upload API through storage helper |
| `.cutmate/storage/intermediates/<project_id>/**` | extracted audio, frames, proxies, analysis scratch outputs that must persist for retry or review | analysis worker through storage helper |
| `.cutmate/storage/exports/<project_id>/**` | rendered downloadable video outputs | export worker through storage helper |
| `.cutmate/storage/thumbnails/<project_id>/**` | generated thumbnail images and previews | analysis/export worker through storage helper |
| `.cutmate/tmp/<job_id>/**` | disposable job-local working files | worker/exporter through storage helper |

No other local app state root is approved for MVP without updating this contract first.

## Storage Keys And Database References

- Database records must store logical artifact references, not raw absolute filesystem paths.
- A logical artifact reference must include the artifact type, owning `project_id`, generated artifact ID where applicable, extension or media kind, and lifecycle status.
- User filenames may be stored only as display metadata after length limiting and escaping. They must not be used for lookup, download, subprocess arguments, logging identity, or output naming.
- `project_id`, `job_id`, export IDs, thumbnail IDs, and other storage identifiers must be generated by the application and validated as strict ID tokens before use.
- IDs used in path construction must be limited to a safe alphabet such as letters, numbers, underscore, and hyphen. Empty IDs, separators, dots as path segments, percent-encoded values, and Unicode path tricks are invalid.

## Storage Helper Responsibilities

All local app file access must go through one storage helper or module, or through a storage configuration object produced by that helper for systems such as SQLite and model runtimes. Direct path construction in endpoints, workers, tests, model management, or UI integration code is not allowed.

The helper must:

- Resolve the active workspace root and `.cutmate/**` roots from configuration or app startup, not from user input.
- Accept only structured inputs such as artifact type, `project_id`, `job_id`, generated artifact ID, and approved extension.
- Map structured inputs to the frozen storage layout in this contract.
- Normalize and canonicalize paths before every read, write, delete, move, or directory listing.
- Reject `..`, `.` path segment abuse, absolute paths, drive-qualified paths, UNC paths, rooted paths, mixed separator traversal, encoded traversal, double-encoded traversal, null bytes, and control characters.
- Reject or fail closed when any path segment or final target is a symlink, junction, hard-link escape, reparse point, or other filesystem indirection that could escape the configured root.
- Confirm the final canonical path remains inside the expected configured root after parent creation and before file access.
- Create storage directories with restrictive local permissions where the platform supports them.
- Use atomic writes for completed artifacts where practical: write into a job temp path first, then move through the helper into the final artifact path.
- Return logical artifact references or API download identifiers, never raw local paths, to frontend or public API clients.
- Provide a safe deletion API that deletes only known artifact roots for a project or job.

The helper must not:

- Accept raw relative paths from request body, query string, route params, headers, database fields, model output, or subprocess output.
- Join user input into filesystem paths.
- Fall back to public/static directories for convenience.
- Return absolute paths in API responses, logs, UI errors, or analytics events.

## Upload Contract

Supported upload formats for MVP:

- `mp4`
- `mov`
- `m4v`

Upload validation must enforce:

- Extension allowlist: only `.mp4`, `.mov`, `.m4v`.
- Container/media validation using server-side metadata extraction, not extension alone.
- Maximum duration: 20 minutes, equivalent to 1200 seconds.
- Maximum upload size: 2 GB (`2_147_483_648` bytes).
- File must be stored as `.cutmate/storage/uploads/<project_id>/source.<ext>`.
- Upload must fail closed if duration, container, extension, size, or metadata extraction cannot be validated safely.
- Analysis job creation must not start until upload validation and storage write complete.
- Videos over 20 minutes must not create an analysis job.

Upload handling must not:

- Preserve user filenames as storage names.
- Trust client-provided MIME type, extension, duration, or file size as the only validation.
- Store source videos in `public/**`, `static/**`, app build output, web asset folders, or temp directories outside `.cutmate/**`.
- Include raw local path, raw tool stderr, or full FFmpeg command output in user-visible errors.

## Intermediate And Temporary Files

- Intermediates that are needed for retry, preview, subtitle sync, thumbnail candidate review, or export must live under `.cutmate/storage/intermediates/<project_id>/**`.
- Disposable worker scratch files must live under `.cutmate/tmp/<job_id>/**`.
- Temp files must include only generated job IDs and generated artifact names.
- A job cleanup step must remove `.cutmate/tmp/<job_id>/**` after success, failure, cancellation, or project deletion.
- Failed jobs may keep structured failure metadata in the database, but must not keep raw command stderr, full local paths, or unbounded logs.
- Intermediates must be deleted with the project unless a future contract explicitly defines user-controlled retention.

## Export And Thumbnail Contract

Exports must live under:

```text
.cutmate/storage/exports/<project_id>/
```

Thumbnails must live under:

```text
.cutmate/storage/thumbnails/<project_id>/
```

Export and thumbnail artifact filenames must be generated by the application. Recommended logical naming may include generated IDs and safe extensions, for example `export_<export_id>.mp4` or `thumbnail_<thumbnail_id>.jpg`, but implementation must keep naming centralized in the storage helper.

Export behavior must enforce:

- Export jobs read only the project's validated source, accepted edit decisions, generated intermediates, and approved thumbnail/crop settings.
- Export paths are allocated before rendering through the storage helper.
- Partially rendered files stay in `.cutmate/tmp/<job_id>/**` or a helper-approved incomplete path until completed.
- Completed exports are moved into `.cutmate/storage/exports/<project_id>/**` only after successful render validation.
- Thumbnail downloads map to generated thumbnail artifact references, not local path strings.
- Internal thumbnail scores remain internal and must not be embedded in public filenames or user-facing download metadata.

## Download Contract

Download URLs must be application routes, not filesystem paths.

Allowed download targets:

- Completed export video owned by the requesting user.
- Selected or generated thumbnail image owned by the requesting user.
- Future contract-approved artifacts only after contract update.

Every download request must check:

- Requesting user is authenticated when auth exists.
- Requesting user or local user context owns the project, or is otherwise authorized by a future explicit sharing contract.
- Project exists and is not deleted.
- Artifact exists in the database as a logical artifact reference.
- Artifact belongs to the requested project.
- Artifact status is downloadable, such as completed or selected.
- Storage helper resolves the artifact to an allowed path under the correct root.

Download responses must not:

- Expose absolute local paths.
- Expose `.cutmate/**` path fragments as stable public URLs.
- Serve originals by default. Original source download requires a future explicit product decision and contract update.
- Serve files from Next.js `public/**`, FastAPI static mounts, or any direct static file directory.
- Leak whether another user's project or artifact exists.

## Deletion Lifecycle

Project deletion has two required phases.

### Immediate Access Block

When a project is deleted:

- Set project status to `deleted` and record `deleted_at`.
- Stop new analysis, export, thumbnail, and download actions for the project.
- Cancel or mark running jobs as cancellation requested where supported.
- All API reads and downloads for the project must return a deleted/not-found style response without exposing local file state.
- Frontend must no longer display the project as accessible.

### Physical Deletion Within 24 Hours

Within 24 hours of deletion, cleanup must remove:

- `.cutmate/storage/uploads/<project_id>/**`
- `.cutmate/storage/intermediates/<project_id>/**`
- `.cutmate/storage/exports/<project_id>/**`
- `.cutmate/storage/thumbnails/<project_id>/**`
- related `.cutmate/tmp/<job_id>/**` directories
- database file-artifact references for originals, intermediates, outputs, and thumbnails

The application may retain a minimal project tombstone only if needed to enforce deletion state, retries, or auditability. A retained tombstone must not include user filenames, absolute paths, raw media metadata beyond what is required, thumbnails, subtitles, transcript text, or generated media references.

Deletion must be idempotent. Re-running cleanup for an already-deleted project must not delete unrelated files or fail in a way that restores access.

## Public And Static File Restrictions

The following are forbidden for originals, intermediates, exports, thumbnails, temp files, models, and local DB files:

- `apps/web/public/**`
- `apps/web/.next/**`
- `apps/api/static/**`
- `public/**`
- `static/**`
- `dist/**`
- `build/**`
- any directory directly served without per-request authorization

If a static route is needed for local previews, it must be implemented as an authorized application route that streams from a storage-helper-resolved artifact after ownership and deletion checks.

## Logging And Error Hygiene

Logs, API errors, UI errors, analytics, and job failure messages must:

- Use stable error codes and short safe messages.
- Redact active workspace paths, `.cutmate/**` paths, usernames, drive letters, and absolute paths.
- Redact raw command arguments that contain local paths.
- Store only bounded, sanitized excerpts when a tool failure needs diagnostics.
- Avoid raw FFmpeg, model runtime, shell, or Python trace stderr in database records and user-visible messages.

Developers may inspect local diagnostic output during development, but persisted app logs and user-facing responses must follow this contract.

## Gitignore And Artifact Hygiene

The active workspace must ignore generated local state and heavy artifacts.

Required ignore patterns:

```text
.cutmate/storage/**
.cutmate/tmp/**
.cutmate/models/**
.cutmate/*.db
.cutmate/*.sqlite
.cutmate/*.sqlite3
```

The SQLite database, uploaded videos, generated media, thumbnails, temp files, and model weights must not be committed.

`.env.example` may document dummy storage variables only. Real `.env`, `.env.local`, app-local env files, local DB files, generated secrets, and media artifacts must not be read or committed by implementation agents.

## Verification Tests Required Before Implementation Completion

Implementation work touching this contract must include focused tests or an explicit owner for each test gap.

### Storage Helper Tests

- Resolves each approved artifact type to the expected `.cutmate/**` root.
- Rejects `../`, `..\\`, mixed separators, absolute POSIX paths, Windows drive paths, UNC paths, rooted paths, null bytes, and control characters.
- Rejects encoded traversal such as `%2e%2e`, `%252e%252e`, encoded slashes, and mixed encoded separators.
- Rejects user filenames as storage names.
- Rejects symlink, junction, reparse-point, or hard-link escape attempts.
- Confirms canonical resolved paths remain under the configured root.
- Deletes only the requested project or job artifact roots.

### Upload Tests

- Accepts valid `mp4`, `mov`, and `m4v` files under duration and size limits.
- Rejects unsupported extensions and mismatched or unreadable containers.
- Rejects videos longer than 20 minutes before analysis job creation.
- Enforces the 2 GB (`2_147_483_648` bytes) max upload size.
- Stores upload as `.cutmate/storage/uploads/<project_id>/source.<ext>`.

### Download Tests

- Allows download of a completed export or selected thumbnail only for the owning user.
- Blocks downloads for deleted projects immediately.
- Blocks downloads for artifacts owned by another project or user.
- Does not expose local paths in response bodies, headers, logs, or UI errors.
- Does not serve originals unless a future contract explicitly allows it.

### Deletion Tests

- Marks deleted projects inaccessible immediately.
- Cancels or blocks queued/running jobs for deleted projects.
- Removes originals, intermediates, outputs, thumbnails, temp files, and file-artifact DB references within the deletion worker's 24-hour SLA.
- Handles repeated cleanup idempotently.
- Does not delete adjacent project directories with similar IDs.

### Artifact Hygiene Tests

- Verifies generated files are under `.cutmate/**`.
- Verifies no originals, exports, thumbnails, DB files, temp files, or model weights are created in public/static/build directories.
- Verifies required ignore patterns cover local generated state.
- Verifies sanitized errors do not include full local paths or raw command stderr.

## Contract Impact

- Backend API must expose only logical artifact IDs or authorized download routes.
- Database design must model artifact ownership, lifecycle status, deletion state, and logical storage references without raw absolute paths.
- Analysis and export workers must use the shared storage helper for every media read/write/delete.
- Frontend must not assume files are static assets; it must request previews and downloads through API routes.
- QA must include path traversal, ownership, deleted-project, and generated artifact hygiene checks.

## Security Impact

This contract mitigates the main MVP file risks:

- path traversal from upload/download/export inputs
- unauthorized access to another user's media
- accidental static serving of private originals or outputs
- generated artifact commits
- symlink or junction escape from `.cutmate/**`
- local path disclosure through errors and logs
- incomplete deletion after user-requested project removal

Any implementation that bypasses the storage helper, exposes raw local paths, or serves media from public/static folders is contract-breaking and must stop for security review.

## Expansion Notes

- MVP max upload size is fixed at 2 GB (`2_147_483_648` bytes).
- Future expansion must keep storage-helper validation, upload API validation, UI copy, and tests aligned.
