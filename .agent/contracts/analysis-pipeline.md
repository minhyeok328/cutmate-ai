# CutMate AI Analysis Pipeline Contract

This contract freezes the CutMate AI MVP local analysis pipeline interface for backend, worker, frontend, QA, and review agents.

It is self-contained for implementation workers. If this contract conflicts with root workspace rules, workspace profile rules, or a higher-priority user instruction, stop and ask the orchestrator before implementation.

## Contract Metadata

- Active workspace: `workspaces/cutmate-ai`
- Contract path: `.agent/contracts/analysis-pipeline.md`
- Workflow mode: Full Delivery, contract-first coordination
- Owning role: Integration Coordinator Agent
- Primary implementation owner: Local Analysis Worker
- Required companion contracts before implementation: `media-storage`, `data-model`, and API DTO contracts. If any are missing, implementation workers must stop and request them.
- Git steward: required before commit

## Non-Negotiable Guarantees

- Core candidate detection must work without any LLM installed.
- Local analysis is the MVP default and must not require an external API key.
- External API mode is disabled for MVP by default.
- `Qwen/Qwen3-8B` is the default local LLM profile when a local LLM is available.
- `openai/gpt-oss-20b` is the quality local LLM profile and is self-hosted local inference, not OpenAI API usage.
- FFmpeg, faster-whisper, OpenCV, PySceneDetect, and OpenCLIP are local tools.
- The local LLM is auxiliary only: recommendation rationale, subtitle cleanup, and user intent parsing.
- The local LLM must not be the core decision-maker for cut, highlight, or thumbnail candidate detection.
- Cut candidates are recommendations only. They are never auto-applied to the edit draft.
- Thumbnail candidates must come from actual video frames. Generative thumbnail images are out of MVP scope.
- Internal numeric scores, raw local paths, raw prompts, raw stderr dumps, secrets, and private runtime metadata must not be returned to clients.
- Model downloads must use allowlisted model IDs and sources. Arbitrary user-provided model URLs are forbidden.

## Pipeline Ownership Boundary

The analysis pipeline owns:

- media validation inputs needed to decide whether analysis can start
- local tool orchestration for metadata, audio, frame, transcript, scene, candidate, and rationale generation
- no-LLM fallback behavior
- progress event emission
- internal worker result assembly
- safe error categorization for API and UI projection

The analysis pipeline does not own:

- user authentication or project authorization
- direct public download URL generation
- raw storage path construction outside the storage helper
- UI state management
- database migrations or schema changes unless assigned by a data-model task card
- export rendering behavior except where analysis outputs feed export choices
- Git, branch, commit, push, or PR behavior

## Terms

- Client: frontend or external caller receiving API responses.
- Worker: local Python analysis worker launched by the backend.
- Storage ref: opaque internal identifier for an original, derivative, frame, audio file, or thumbnail artifact.
- Local path: canonical filesystem path resolved only inside trusted storage/tool adapters.
- Public media URL: authorized, client-safe URL or route produced by the API/storage layer.
- Internal score: numeric quality, relevance, confidence, or ranking value used for sorting and filtering.
- Rationale: user-visible explanation string generated by templates or an auxiliary local LLM.
- Partial result: valid subset of analysis output produced after a recoverable stage failure.

## Analysis Modes

Mode selection is an input enum. Workers must reject unknown mode values.

| Mode | Purpose | Required tools | Optional local model use | Fallback behavior |
| --- | --- | --- | --- | --- |
| `light` | Fast local draft with minimal compute. | FFmpeg, OpenCV, audio-level silence detection. faster-whisper is used when available and audio exists. | None by default. LLM disabled. OpenCLIP optional. | Must produce basic cut, highlight, and thumbnail candidates when FFmpeg/OpenCV succeed. Uses template rationales. Subtitles are skipped if speech recognition is unavailable or fails. |
| `standard` | Default MVP analysis quality. | FFmpeg, faster-whisper when audio exists, OpenCV, PySceneDetect with OpenCV fallback, OpenCLIP when installed. | `Qwen/Qwen3-8B` may be used for rationale, subtitle cleanup, and user intent parsing if installed. | Must complete without LLM. If OpenCLIP is unavailable, use keyword, transcript, scene, and visual-quality signals. If PySceneDetect is unavailable, use OpenCV scene heuristics. |
| `quality` | Higher-quality local self-hosted analysis for users with sufficient hardware. | Standard mode tools plus higher sampling density and stricter ranking passes. | `openai/gpt-oss-20b` as local self-hosted quality LLM. `Qwen/Qwen3-8B` may be fallback for LLM-only auxiliary tasks. | If quality LLM is missing or times out, continue with standard deterministic outputs and mark LLM rationale as template or default-LLM generated. Never call OpenAI API for this mode in MVP. |

Mode behavior must be deterministic enough for tests. LLM output can improve wording but must not change the existence, time range, or ranking eligibility of core candidates unless a future contract explicitly permits that.

## Worker Input Contract

The backend passes a single analysis request to the worker. The request must contain opaque refs and enums, not user-controlled shell fragments or arbitrary paths.

```json
{
  "schema_version": "analysis.request.v1",
  "job_id": "analysis_job_id",
  "project_id": "project_id",
  "user_id": "user_id",
  "source_asset_ref": "storage_ref_for_uploaded_video",
  "mode": "light | standard | quality",
  "content_purpose": "short_form | vlog | lecture | interview | promotional_video",
  "output_goal": "source_summary | highlight_extraction | subtitle_generation | short_form_conversion",
  "user_intent": {
    "title": "optional bounded plain text",
    "primary_keywords": ["optional", "bounded", "plain text"],
    "brand_tone": "optional bounded plain text",
    "prohibited_expressions": ["optional", "bounded", "plain text"]
  },
  "runtime_preferences": {
    "external_api_mode": "disabled",
    "default_llm": "Qwen/Qwen3-8B",
    "quality_llm": "openai/gpt-oss-20b",
    "llm_runtime": "ollama"
  },
  "limits": {
    "max_duration_seconds": 1200,
    "max_upload_size_bytes": 2147483648,
    "stage_timeout_seconds": 900,
    "job_timeout_seconds": 7200
  }
}
```

### Input Validation Rules

- `schema_version` must match this contract version.
- `job_id`, `project_id`, and `user_id` are opaque IDs. They must not be treated as filesystem paths.
- `source_asset_ref` must be resolved through the storage helper only.
- `mode`, `content_purpose`, and `output_goal` must be enum validated.
- `external_api_mode` must be `disabled` for MVP.
- User intent text must be length-limited, treated as untrusted input, and never inserted into subprocess arguments except as bounded data files or model prompt fields.
- Raw upload filenames may be displayed only after escaping and must not be used to form storage paths.
- Videos over 20 minutes must not create an analysis job.
- The MVP upload size limit is 2 GB (`2_147_483_648` bytes). It must be enforced before analysis starts. Future expansion must update the workspace profile, API contract, data model contract, media-storage contract, and validation tests together.
- Timeout values must be positive integers from backend configuration. The values above are the default contract baseline for MVP task cards unless a later contract update changes them.

## Internal Worker Output Contract

The worker returns a structured internal result to the backend. Internal refs and scores may be persisted if authorized by the data-model contract, but client projection must sanitize them.

```json
{
  "schema_version": "analysis.result.v1",
  "job_id": "analysis_job_id",
  "project_id": "project_id",
  "mode": "standard",
  "status": "completed | completed_with_warnings | failed",
  "tool_versions": {
    "ffmpeg": "internal_version_string",
    "faster_whisper": "internal_version_string_or_null",
    "opencv": "internal_version_string",
    "pyscenedetect": "internal_version_string_or_null",
    "openclip": "internal_version_string_or_null",
    "llm_runtime": "internal_version_string_or_null"
  },
  "media": {
    "duration_seconds": 612.4,
    "resolution": { "width": 1920, "height": 1080 },
    "aspect_ratio": "16:9",
    "has_audio": true
  },
  "subtitles": [],
  "cut_candidates": [],
  "highlight_candidates": [],
  "thumbnail_candidates": [],
  "warnings": [],
  "error": null
}
```

### Segment Shape

`subtitles`, `cut_candidates`, and `highlight_candidates` use seconds for internal timing and client-safe IDs for referencing.

```json
{
  "id": "segment_id",
  "start_seconds": 72.3,
  "end_seconds": 88.9,
  "transcript": "optional transcript excerpt",
  "reason": "client-safe rationale",
  "status": "pending",
  "source_signals": ["silence", "speech_density", "scene_change"],
  "internal_score": 0.82
}
```

Rules:

- `internal_score` is internal-only and must not be included in client responses.
- `source_signals` may be returned to clients only after mapping to approved labels.
- `reason` must be plain text with no raw prompts, stack traces, paths, command output, or secrets.
- Time ranges must be clamped to video duration and must satisfy `start_seconds < end_seconds`.
- Segment IDs must be opaque and non-path-like.

### Thumbnail Candidate Shape

```json
{
  "id": "thumbnail_candidate_id",
  "timestamp_seconds": 78.2,
  "image_asset_ref": "storage_ref_for_generated_thumbnail",
  "reason": "client-safe rationale",
  "tags": ["highlight_related", "sharp_frame", "subject_visible"],
  "status": "pending",
  "internal_score": 0.87,
  "safety_flags": []
}
```

Rules:

- `image_asset_ref` must be converted by the API/storage layer into an authorized public media URL or route.
- Thumbnail candidates must be actual frames from the uploaded video.
- Unsafe frames, blurred frames, closed-eye frames when detected, excessive crop risk, sensitive-info exposure, and visually distorted frames must be excluded from default recommendations.
- If fewer than the required number of safe candidates are available, emit `insufficient_thumbnail_candidates` and support direct frame selection.

## Client Projection Contract

Client-facing responses may expose:

- job status
- step name and progress
- retry availability
- subtitles with editable text and timecodes
- cut and highlight candidate time ranges, status, and rationale
- thumbnail candidate timestamp, authorized image URL, tags, status, and rationale
- safe warning or error category

Client-facing responses must not expose:

- raw local filesystem paths
- raw storage refs unless the API contract explicitly marks them client-safe opaque IDs
- raw prompts or user prompt assembly
- raw stderr, stack traces, tool command lines, or full logs
- real env values, secrets, tokens, or model credentials
- internal numeric scores or confidence values
- private tool/runtime versions unless explicitly approved for diagnostics
- source video, audio, frame, or thumbnail URLs without authorization checks

## Progress Event Schema

Progress events are emitted by the worker or backend and projected to the client after sanitization.

```json
{
  "schema_version": "analysis.progress.v1",
  "event_id": "event_id",
  "sequence": 12,
  "job_id": "analysis_job_id",
  "project_id": "project_id",
  "mode": "standard",
  "stage": "speech_recognition",
  "stage_status": "queued | running | skipped | completed | failed | retrying",
  "progress_percent": 42,
  "stage_progress_percent": 60,
  "message_key": "analysis.speech.running",
  "safe_message": "Generating subtitle draft.",
  "retryable": false,
  "partial_results_available": false,
  "error_category": null,
  "occurred_at": "ISO-8601 timestamp"
}
```

Event rules:

- `sequence` must increase monotonically per job.
- `progress_percent` must be an integer from 0 to 100.
- `stage_progress_percent` must be an integer from 0 to 100 or null.
- `safe_message` must be user-safe and must not include raw paths, command lines, stderr, prompts, secrets, or internal scores.
- Failed events must include `error_category`.
- Skipped events must explain the safe reason through `message_key`, for example no audio or optional model unavailable.
- Clients must treat progress as an estimate and must not infer completion until final job status is `completed` or `completed_with_warnings`.

## Pipeline Stages

Stages must emit progress events using the schema above. Stage names are frozen for API, frontend, worker, and QA coordination.

| Order | Stage | Required input | Main tools | Output | Recoverability |
| --- | --- | --- | --- | --- | --- |
| 1 | `queued` | Valid analysis request | None | Job queued event | Recoverable |
| 2 | `validate_media` | Source asset ref and upload metadata | Storage helper, FFprobe through FFmpeg | Format, duration, size, audio presence | Fatal for unsupported format, over duration, over size, unreadable media |
| 3 | `prepare_media` | Valid source asset ref | FFmpeg | Audio asset ref, proxy asset ref, frame sample refs | Fatal if FFmpeg cannot read source; retryable for transient storage errors |
| 4 | `speech_recognition` | Audio asset ref, has_audio true | faster-whisper | Raw transcript segments | Skipped for no audio; recoverable as partial result on failure |
| 5 | `subtitle_assembly` | Transcript segments | Deterministic segmenter, optional local LLM cleanup | Editable subtitle segments | Recoverable; may produce no subtitles |
| 6 | `audio_signal_analysis` | Audio asset ref or transcript timing | Audio levels, optional VAD | Silence, pause, density, repetition signals | Recoverable when no audio; scene-only analysis continues |
| 7 | `scene_detection` | Proxy/frame refs | PySceneDetect, OpenCV fallback | Scene boundaries and visual motion signals | Recoverable through OpenCV fallback |
| 8 | `frame_sampling` | Scene boundaries, proxy refs | FFmpeg, OpenCV | Candidate frame refs | Fatal for thumbnail feature if frame extraction fails |
| 9 | `candidate_detection` | Transcript, audio, scene, frame signals | Deterministic rules | Cut and highlight candidate drafts | Required no-LLM stage |
| 10 | `thumbnail_scoring` | Candidate frame refs | OpenCV | Ranked safe thumbnail candidates with internal scores | Required for default thumbnail candidates |
| 11 | `semantic_matching` | Highlights, keywords, frame refs | OpenCLIP when available | Semantic relevance adjustments | Optional; deterministic fallback required |
| 12 | `rationale_generation` | Candidate drafts, mode, user intent | Templates, optional local LLM | Client-safe rationale strings | Optional LLM; template fallback required |
| 13 | `result_assembly` | All prior stage outputs | Worker result assembler | Analysis result payload | Fatal only if persisted result cannot be assembled |
| 14 | `completed` | Result payload | Backend persistence | Job completion event | Final |
| 15 | `failed` | Error state | Backend persistence | Safe failure event | Final |

## Candidate Detection Requirements

### Cut Candidates

Cut candidate detection must use deterministic local signals first:

- long silence
- long pauses
- speech density drops
- repeated or near-duplicate transcript phrases when transcript exists
- stutter or filler clusters when transcript exists
- low-information waiting segments
- scene/audio discontinuities indicating dead time

Rules:

- Candidate ranges must not be auto-deleted.
- Overlapping candidates must be merged or ranked deterministically before returning.
- A candidate must include a user-safe reason.
- LLMs may rewrite rationale but must not invent time ranges or override deterministic eligibility.

### Highlight Candidates

Highlight recommendation must use local signals first:

- content purpose
- output goal
- speech density
- keyword relevance
- scene changes
- visual quality and stability
- proximity to thumbnail-worthy frames

Rules:

- At least one highlight candidate should be produced when enough valid source material exists.
- If no reliable highlight exists, emit a safe warning and allow manual user selection.
- Quality mode may improve rationale wording and user-intent interpretation, but deterministic signals remain authoritative.

### Thumbnail Candidates

Thumbnail recommendation must use actual video frames and local quality filters:

- blur or focus quality
- brightness and contrast
- composition and crop stability
- subject or product visibility when detectable
- highlight relevance
- sensitive information exclusion
- closed-eye or poor-expression exclusion when detectable
- excessive crop risk for 16:9, 9:16, and 1:1 previews

Rules:

- Default recommendation target is 3 thumbnail candidates.
- Client UI must not display internal scores.
- Direct frame selection must remain available when recommendations are insufficient.
- Generated thumbnails that create new scene content are out of MVP scope.

## Local Tool Fallback Behavior

| Tool/model | Role | If unavailable | If runtime fails or times out |
| --- | --- | --- | --- |
| FFmpeg/FFprobe | Metadata, audio extraction, proxy/frame extraction | Fatal `tool_unavailable` because media cannot be prepared safely | Retry once if safe; otherwise `tool_failed` or `tool_timeout` |
| OpenCV | Visual quality, frame validation, fallback scene heuristics | Fatal for default thumbnail candidate generation; analysis may return subtitle/cut partials only if already produced | `tool_failed`; partial results allowed if cut/subtitle stages succeeded |
| faster-whisper | Speech recognition and subtitle draft | Skip subtitles and transcript-dependent signals; continue scene, visual, and audio-level analysis | `speech_recognition_failed`; partial result allowed |
| PySceneDetect | Scene transition detection | Use OpenCV scene-change fallback | Use OpenCV scene-change fallback and warning |
| OpenCLIP | Semantic frame/highlight matching | Use transcript keyword, scene, and visual-quality fallback | Use deterministic fallback and warning |
| `Qwen/Qwen3-8B` | Default local LLM for rationale, subtitle cleanup, intent parsing | Use template rationales and raw deterministic subtitle text | Use template rationales; preserve deterministic candidates |
| `openai/gpt-oss-20b` | Quality local LLM for auxiliary quality mode text tasks | Use `Qwen/Qwen3-8B` if locally available, otherwise templates | Use fallback LLM or templates; never call OpenAI API |

Fallback warnings must be internal-safe and client-safe after mapping. They must not expose local paths, command lines, stack traces, raw stderr, prompts, or model cache locations.

## Local Model And Runtime Boundary

Allowed MVP local LLM IDs:

| Profile | Model ID | Mode | Source policy |
| --- | --- | --- | --- |
| Default local LLM | `Qwen/Qwen3-8B` | `standard`, optional | Allowlisted source only |
| Quality local LLM | `openai/gpt-oss-20b` | `quality`, optional | Allowlisted source only; self-hosted local runtime; not OpenAI API |

Runtime rules:

- `CUTMATE_EXTERNAL_API_MODE` defaults to `disabled`.
- MVP analysis must not send video, audio, subtitles, frames, thumbnails, prompts, project metadata, or user intent to external APIs by default.
- Local runtime adapters must use explicit model IDs from the allowlist.
- User-provided URLs, arbitrary model IDs, arbitrary local model paths, and remote code execution options are forbidden.
- Model downloads must be explicit user-triggered setup actions or documented install steps, not hidden side effects during analysis.
- Runtime prompts must be assembled from fixed templates with bounded user text fields.
- Runtime responses must be parsed as untrusted text and sanitized before client display.
- Runtime failures must not block deterministic candidate output.
- Local model cache paths, prompt text, and raw response logs are internal diagnostics only.

Supported runtime priority for MVP:

1. Ollama for local LLM invocation.
2. LM Studio, llama.cpp, or vLLM only after an implementation task explicitly adds and verifies an adapter.

## Safe Subprocess Boundary

All local tool invocations must satisfy these rules:

- No `shell=True`.
- No shell command strings.
- No user input interpolated into commands.
- Use argument arrays only.
- Use a fixed, workspace-approved current working directory.
- Resolve all input and output files through storage/tool helpers before invocation.
- Canonicalize paths and reject paths outside approved storage roots.
- Disable network-capable tool behavior where the tool supports external protocols.
- Set per-stage timeouts and job-level timeouts.
- Apply configured resource limits for CPU, memory, process count, output size, and temporary disk use where the platform supports them.
- Kill the full process group on timeout or cancellation.
- Capture stdout/stderr only into bounded internal logs.
- Redact or drop raw stderr before client projection.
- Allowlist tool operations by adapter, for example metadata probe, audio extraction, proxy generation, frame extraction, scene detection, and local model invocation.
- Reject attempts to pass arbitrary filters, scripts, URLs, devices, protocols, or output destinations from user input.

Subprocess adapters must expose typed operations such as `probe_media`, `extract_audio`, `extract_proxy`, `sample_frames`, and `extract_thumbnail_frame` to callers. Workers must not construct ad hoc subprocess calls outside adapters.

## Error Categories

Workers and API projections must use these categories. Client messages may be localized later, but the category values are frozen.

| Category | Typical source | Retryable | Client-safe behavior |
| --- | --- | --- | --- |
| `validation_failed` | Missing or invalid request fields | No | Ask user to retry upload or correct request |
| `unsupported_format` | File extension/MIME/probe mismatch | No | Explain supported formats |
| `duration_exceeded` | Video over 20 minutes | No | Explain MVP 20-minute limit |
| `size_exceeded` | File exceeds configured max size | No | Ask user to compress or upload shorter video |
| `media_unreadable` | Corrupt or unreadable source | Sometimes | Ask user to re-upload or use another file |
| `no_audio` | Source has no audio stream | No failure | Skip subtitles and continue visual analysis |
| `tool_unavailable` | Required local tool missing | No until installed | Tell user required local tool is unavailable |
| `tool_timeout` | Tool exceeded timeout | Yes when resource conditions change | Offer retry or lighter mode |
| `tool_failed` | Local tool returned failure | Sometimes | Show failed stage without raw stderr |
| `resource_limit_exceeded` | Memory, disk, CPU, process, or temp limit exceeded | Sometimes | Suggest lighter mode or smaller video |
| `speech_recognition_failed` | faster-whisper failure | Yes | Continue with no-subtitle partial result when possible |
| `model_unavailable` | Optional local LLM missing | No failure | Use template rationale fallback |
| `model_timeout` | Optional local LLM exceeded timeout | No failure by default | Use fallback rationale |
| `model_download_blocked` | Non-allowlisted source/model requested | No | Explain only allowlisted local models are supported |
| `external_api_disabled` | Any attempt to use external API in MVP default mode | No | Explain external API mode is disabled |
| `storage_error` | Storage helper cannot read/write refs | Sometimes | Retry if transient; do not expose paths |
| `result_assembly_failed` | Internal result cannot be assembled or persisted | Yes if transient | Show analysis failed and retry availability |
| `internal_error` | Unexpected worker/backend exception | Sometimes | Generic safe failure message |

Fatal errors set job status to `failed`. Recoverable stage failures set job status to `completed_with_warnings` when enough valid results exist.

## Security And Privacy Requirements

- Do not read `.env`, `.env.local`, app-local env files, credentials, local databases, uploaded media, generated outputs, or model weights unless a specific implementation task explicitly owns that path and the workspace profile allows it.
- Do not return unauthorized media URLs or storage refs to clients.
- Authorize every project, analysis result, thumbnail, and generated asset access server-side.
- Validate all user-controlled text by type, length, and enum before storage, subprocess, model prompt assembly, or UI display.
- Escape subtitles, filenames, rationale text, and errors before UI rendering.
- Never log secrets, raw prompts, raw user media paths, raw stderr dumps, or full model responses into client-visible logs.
- Persist only the minimum internal diagnostics needed for retry and developer debugging.
- Project deletion must block access immediately and leave physical deletion scheduling to the storage contract.
- Security Review Agent is required for implementation touching subprocess adapters, file handling, storage refs, model download/runtime setup, user-controlled text rendering, or external API configuration.

## Verification Expectations For Implementers

Implementation workers must add focused verification for their owned scope. At minimum, future implementation must prove:

- Request validation rejects unknown modes, unknown enums, arbitrary model IDs, arbitrary model URLs, and enabled external API mode.
- A no-LLM environment still produces deterministic cut, highlight, and thumbnail candidate output for a valid small sample video when FFmpeg/OpenCV succeed.
- Missing optional LLM emits fallback/template rationale and does not fail the job.
- Missing OpenCLIP or PySceneDetect falls back deterministically.
- No-audio videos skip subtitle generation and continue visual analysis.
- Over-20-minute videos do not create analysis jobs.
- Client projection omits internal scores, raw local paths, raw prompts, raw stderr, stack traces, and storage internals.
- Subprocess adapters use argument arrays, fixed cwd, timeouts, and allowlisted operations.
- Tool failures map to the frozen error categories.
- Progress events follow `analysis.progress.v1` and sequence monotonically.
- Thumbnail candidates are actual video frames and unsafe/low-quality frames are excluded from default recommendations where detection is available.

Suggested future command families are listed in the workspace profile. Concrete commands belong in the implementation task card because the app scaffold may not exist yet.

## Contract Drift Rules

Implementation must stop and request a contract update before:

- adding a new analysis mode
- adding or renaming progress stages
- exposing internal scores or raw diagnostics to any client
- allowing external API analysis by default
- allowing user-provided model URLs or arbitrary model IDs
- changing `openai/gpt-oss-20b` from local self-hosted mode to API mode
- making LLM output authoritative for candidate time ranges or eligibility
- adding public API fields not covered by API and data-model contracts
- broadening subprocess operations beyond the allowlisted adapter operations

## Needs Confirmation

These are unresolved product choices that affect implementation behavior:

- Official CPU-only support level for `standard` and `quality` modes. This contract assumes CPU-only is supported for `light` and no-LLM fallback, while GPU or Apple Silicon is recommended for heavier modes.
- Model download automation extent. This contract allows only manual setup or explicit user-triggered allowlist downloads, but final UX is not frozen.
- Final allowed model source list and checksum/signature policy for `Qwen/Qwen3-8B`, `openai/gpt-oss-20b`, faster-whisper profiles, and OpenCLIP profiles.
- Behavior when fewer than 3 safe thumbnail candidates are available: direct selection only vs. lower threshold with explicit quality warning.
- Whether runtime priority after Ollama should include LM Studio, llama.cpp, vLLM, or only one of them for MVP.
